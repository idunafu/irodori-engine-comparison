# Irodori-TTS 自動品質評価の結果

2026年10月16〜19日に実施した、公式CUDA版・ONNX CUDA版・speech.cpp Vulkan版の読みと話者再現性の比較です。主比較と同じ固定コード・モデル・runtimeを使用し、MFは3実装、RFは公式版とspeech.cppを評価しました。[評価条件・実行手順](../../quality/README.ja.md)も参照してください。

後続の[speech.cpp更新後の100話者・1クリップ参照評価と原因診断](../jvs-latest-20261019/RESULTS.ja.md)は別ページへ保存しています。このページの主評価は当初の固定コミットの結果です。

JKYBの読み正解率は実用精度でMF 92.57〜92.78%、RF 93.38〜93.40%でした。実用文ではspeech.cppが長文8件を30秒制限で拒否するため、全40文の失敗込み集計と共通成功32文の集計を分けます。JVSでは長い参照によって話者再現性が上がる一方、1クリップ参照のspeech.cppには低下が見られました。追加診断では参照のリサンプルとVulkan codecの内部F16演算による数値差を確認しています。

自動指標は読み戻し・話者埋め込みの評価です。試聴、自然さ、caption指示追従は評価しておらず、聴感上の品質同等性は結論しません。

読み・実用文のrun `20261016-reading` は全354,900要求を処理済みですが、共通ノイズ診断のQwen採点3件が`model_limit`で失敗し、最終状態は`failed`です。160件の生成失敗はspeech.cppの長文拒否、40件は`number-money`の出力長検査での1サンプル差です。この40件は共通条件の秒数を浮動小数点からサンプル数へ切り捨てたことに起因し、音声品質の失敗とは区別します。採点失敗3件は生成失敗200件とは別です。[coverage.json](reading/coverage.json)と[生成失敗一覧](reading/failures.csv)に記録しています。

JVSのrun `20261018-jvs` は60,000件の生成・CAM++・Whisper採点すべて完了しました。さらに別枠で、JVS参照経路診断3,000音声、サンプルレート比較3,600音声、F16重み比較900音声が生成・採点とも完了しています。ダウンロード待ちで中断した初期run `20261016` と、準備用・見積もり用の試行は上表に加算しません。

## JKYB：漢字の読み

全13,536文、参照音声・captionなし。正解率は対象語の`target_exact`、文かなCERは`sentence_kana_cer`です。いずれも5 seed平均、正解率は高いほど、CERは低いほど良好です。

| 構成 | 読み正解率 | 文かなCER |
|---|---:|---:|
| 公式 MF BF16 | 92.620% | 1.546% |
| ONNX MF FP16 | 92.569% | 1.550% |
| speech.cpp MF F16 | 92.778% | 1.503% |
| 公式 RF BF16 | 93.384% | 1.304% |
| speech.cpp RF F16 | 93.395% | 1.333% |

公式との差はONNX MF −0.050ポイント、speech.cpp MF +0.158ポイント、speech.cpp RF +0.012ポイント。漢字読みの組4,512群を単位とする対応ありbootstrap 95%区間は、それぞれ[−0.189, +0.093]、[+0.004, +0.306]、[−0.114, +0.127]ポイントです。speech.cpp MFには小さな正の差がありますが、ここから一般的な音質の優位性は導けません。

FP32は固定500文の抜粋です。全13,536文の実用精度との単純な平均値比較は避け、同じ抜粋で比較した`fp32_minus_practical`を参照してください。[全指標・種別別集計](reading/summary.csv)、[seed別値と分母](reading/per-seed.csv)、[公式との差・精度差と95%区間](reading/comparisons.csv)を保存しています。

### RFの生成長・初期ノイズを揃えた診断

出力長検査の1サンプル差があった`number-money`も全条件から除いた31文×5 seedで比較します。FP32でも通常条件のReazon差は+4.87ポイント残りましたが、生成長・初期ノイズを共有すると+0.09ポイント、Qwen差は+0.15ポイントになりました。共通条件の差の95%区間はいずれも0を含みます。生成長が元から同じ27文でも、Reazon差は通常+6.58ポイントから共通ノイズ0.00ポイントへ縮小しました。

同じseed番号でも実装間の初期ノイズは異なります。今回の差には有限の5 seedとASRの感度が影響したと推定します。代表8音声を第三のWhisperで確認したところ、Reazonで文の一部を取りこぼしたspeech.cppの4音声も、QwenとWhisperでは内容全体を認識できました。これは一部の例の原因診断であり、全件スコアには混ぜていません。

詳細は[共通成功32文](common-success-native/RESULTS.ja.md)、[RFの原因調査](rf-cause/RESULTS.ja.md)、[共通ノイズ・長さの155組の照合](rf-cause/common-condition-audit.csv)、[第三ASRの記録](rf-cause/whisper-check.json)を参照してください。文間の声の一貫性は埋め込みが揃う別の共通25文で評価しており、JVSの参照話者への類似度とは異なります。

## JVS：話者再現性と参照長

全100話者、各5文、5 seed。1クリップ／約30秒／約60秒／120秒の4参照条件を比較しました。約30・60秒は最後のクリップを保持し、120秒のみ切り詰めます。照合centroidは合成対象と別の10発話から作成し、全構成で共通です。下表の各セルはCAM++ cosineと話者Top-1の組で、各参照条件・各構成2,500音声の5 seed平均です。

| 構成 | 1クリップ：cosine / Top-1 | 約30秒 | 約60秒 | 120秒 |
|---|---:|---:|---:|---:|
| 公式 MF BF16 | 0.764480 / 88.64% | 0.819255 / 98.36% | 0.826202 / 98.52% | 0.831954 / 99.12% |
| ONNX MF FP16 | 0.762380 / 88.44% | 0.817992 / 98.40% | 0.825488 / 98.80% | 0.831410 / 99.32% |
| speech.cpp MF F16 | 0.756571 / 84.52% | 0.819517 / 98.64% | 0.826850 / 99.20% | 0.832217 / 99.32% |
| 公式 RF BF16 | 0.768389 / 88.96% | 0.827857 / 98.64% | 0.833915 / 99.16% | 0.839892 / 99.56% |
| speech.cpp RF F16 | 0.759178 / 84.28% | 0.829778 / 99.04% | 0.837049 / 99.36% | 0.843358 / 99.40% |

1クリップではspeech.cppのTop-1は公式よりMFで4.12ポイント、RFで4.68ポイント低い点推定でした。約30秒以上では全構成のTop-1が98%以上となり、この数ポイントの差は縮小しています。参照長をまとめた全体平均だけでは短い参照の差が隠れるため、参照長別に掲載しています。[全指標・FP32・参照長別CSV](jvs/summary.csv)、[seed別値と分母](jvs/per-seed.csv)、[4参照条件をまとめた公式との差・95%区間](jvs/comparisons.csv)、[完了件数](jvs/coverage.json)を保存しています。主評価の区間は100話者単位で、参照長別の区間ではありません。

### 1クリップ参照の経路診断

固定20話者で公式前処理PCM・codec latent・話者特徴量を順に交換しました。MFは5文×5 seed、RFは先頭1文×5 seedで、全条件FP32重み・共通生成長・共通ノイズです。

同じ公式PCMをcodecへ入れたときのlatent相対L2誤差は、通常Vulkanで0.09379、内部F16経路を無効化すると約0.00000310でした。重みがFP32でも内部F16の丸めが残ります。また公式とspeech.cppではリサンプル方式が異なり、同じlatentからの話者特徴量cosineは約0.999996でした。

MFのCAM++ cosine差は、通常参照−0.003280、公式PCM使用−0.001248、公式latent使用−0.000182、公式話者特徴量使用−0.000013でした。参照波形からlatentまでの差が生成後の話者類似度へ影響することを確認した実験です。全100話者での補正後スコアは未測定であり、20話者の点推定を主評価の低下量に直接当てはめません。[診断結果と区間](jvs-one-reference/RESULTS.ja.md)、[3,000音声の検証記録](jvs-one-reference/validation.json)を参照してください。

## 入力サンプルレートとF16重みの追加診断

つくよみちゃん1話者の96kHz原音から、96・48・44.1・32・24・16kHzのfloat32 WAVを直接作成しました。元音源のID050は48kHzのため波形比較から除外しています。波形比較は99発話、生成参照は001〜005、照合は別の011〜020、合成対象は021〜023です。

FP32診断は公式・通常Vulkan・内部F16無効Vulkan・公式へspeech.cpp前処理PCMを渡す4条件を比較しました。MF/RF・各5 seedで3,600音声。全条件で公式48kHz参照の生成長と初期ノイズを共有しています。

48kHz入力ではリサンプルを通らず、波形は一致しました。同じPCMと内部F16無効の組み合わせでlatent相対L2差は全入力レートで約0.00028〜0.00032%まで縮まりました。一方、異なるリサンプルを含むlatent差は入力レートによって変わります。数値差の割合は音質低下率を意味しません。

追加の900音声ではspeech.cppのTTS本体のみF16重みへ変更しました。codec latentはFP32重み実行時と完全一致し、生成長・ノイズ・照合centroidも共有しています。CAM++ cosineのF16−FP32差はMF/RF・6レートで−0.000254〜+0.000231（cosine×100表示で−0.0254〜+0.0231ポイント）でした。重みのF16化による差と、codec内部のF16演算経路による差を区別する必要があります。

これは1話者・参照5クリップの結果です。95%区間は参照クリップ単位であり、話者集団への区間ではありません。入力レートの一般的な優劣、読みの正確さ、聴感品質までは判断しません。[FP32の詳細表](sample-rate/RESULTS.ja.md)、[F16重みの詳細表](sample-rate-f16/RESULTS.ja.md)、[FP32検証記録](sample-rate/validation.json)、[F16検証記録](sample-rate-f16/validation.json)を参照してください。

音声・モデル・コーパス・SQLite・詳細JSONL・ログ・ビルド成果物はローカルの`artifacts/quality/`に保持し、Gitへ含めません。ルートのコーパスZIPもGit管理外です。データを削除・移動せず、結果の公開用コピーを作成しています。公開manifest中の既存の`fingerprint`や参照先ファイルのSHA-256は測定時の元データを識別する値であり、公開用にパスを正規化したmanifest自体のハッシュではありません。再開時の照合には元runのmanifestを使います。

追加診断の小さなPython/C++コードは、各診断フォルダーの`source/`へ保存しました。元コードはrunフォルダーを基準にパスを解決するため、直接この公開コピーからは実行せず、`provenance.json`の`source`に示す元の相対パスへ配置して使います。JVS参照経路とサンプルレート診断には、元の派生speech.cppビルド・診断バイナリ・中間保存物が必要であり、この公開フォルダーだけで再生成できる構成ではありません。

元のデータがある環境では、以下で再集計できます。GPU推論やASRの再実行は不要です。

```bash
.venvs/quality/bin/python benchmark/quality/report.py artifacts/quality/runs/20261016-reading
.venvs/quality/bin/python benchmark/quality/report.py artifacts/quality/runs/20261018-jvs
.venvs/quality/bin/python artifacts/quality/runs/20261016-reading/analysis/common-success-native/recompute.py
.venvs/quality/bin/python artifacts/quality/runs/20261016-reading/analysis/rf-cause/recompute.py
.venvs/quality/bin/python artifacts/quality/runs/20261018-jvs/analysis/one-reference/analyze.py
.venvs/quality/bin/python benchmark/quality/sample_rate/analyze.py
.venvs/quality/bin/python benchmark/quality/sample_rate_f16/run.py --report-only
```

元の主評価は`report.py`内で音高・声の一貫性の再解析も行うため、生成音声とspeech-benchの環境が必要です。再集計結果は元runの出力先へ書き出され、この公開用コピーは自動更新されません。
